# Задание 2. FURPS+ таблица

| Код | Требования                                                                                                                                                                                                          | Комментарий                                                                                                            |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| F   | Функциональные (Functionality)                                                                                                                                                                                      |                                                                                                                        |
| F1  | На сайте пользователь видит текущие условия по депозитам и может подать заявку с Ф.И.О. и номером телефона.                                                                                                         | Требование к первой digital-витрине; важно отразить актуальные ставки.                                                 |
| F2  | После заявки на сайте менеджер кол-центра связывается с клиентом, может предложить индивидуальные условия.                                                                                                          | Для части новых клиентов — "ручное дожимание" конверсии.                                                               |
| F3  | В интернет-банке клиент видит доступные депозиты с персональными ставками, выбирает счёт, сумму, подает заявку онлайн.                                                                                              | Нужна связка с клиентским профилем и резервированием ставки.                                                           |
| F4  | Подтверждение операции через СМС (интернет-банк).                                                                                                                                                                   | Требует интеграции с действующим СМС-шлюзом; важно не "ломать" текущую СМС-авторизацию.                                |
| F5  | После ручной обработки в бэк-офисе клиент получает СМС с подтверждением суммы ставки и об открытии депозита.                                                                                                        | Требование к интеграции СМС-уведомлений после ручной проверки.                                                         |
| F6  | Актуализация тарифов (ставок) должна быть возможна для бэк-офиса депозитов и кредитов из единого места.                                                                                                             | Сейчас ставки в XLS — должна появиться централизованная цифровая админка/хранилище ставок.                             |
| F7  | 7. Все действия пользователя должны логироваться.                                                                                                                                                                   | Требование ИБ и аудита, стандарт в финтехе.                                                                            |
| U   | Удобство использования (Usability)                                                                                                                                                                                  |                                                                                                                        |
| U1  | Минимальное количество шагов при оформлении заявки.                                                                                                                                                                 | Снижение порога входа, борьба с оттоком "по дороге".                                                                   |
| U2  | Актуальное отображение ставок и персонализация (интернет-банк).                                                                                                                                                     | Персональный оффер — конкурентное преимущество онлайн-канала.                                                          |
| U3  | Быстрый отклик интерфейса (миллисекунды), сплошной бренд-дизайн и фирменные элементы.                                                                                                                               | Подтверждает требования бизнеса к CX, антипаттерны из текущего интернет-банка должны быть устранены.                   |
| U4  | Доступность всех форм и функций для маломобильных пользователей.                                                                                                                                                    | Стандарт для публичных финсервисов (WCAG).                                                                             |
| U5  | Возможность получать push/SMS/email-уведомления о статусе заявки.                                                                                                                                                   | Меньше обращений в поддержку, выше прозрачность.                                                                       |
| R   | Надёжность (Reliability)                                                                                                                                                                                            |                                                                                                                        |
| R1  | Защищённая передача пользовательских данных (HTTPS/TLS минимум для сайта и интернет-банка).                                                                                                                         | Архитектурно значимо! Прямое требование регулятора и финбезопасности.                                                  |
| R2  | Непрерывная доступность сервисов (99.9% SLA), включая ЦОД и резервирование.                                                                                                                                         | В перспективе критично, сейчас потенциальный риск.                                                                     |
| R3  | Заявки и уведомления не теряются при сбоях — должна быть реализована система гарантированной доставки (минимум retry-queue на письма и СМС).                                                                        | Важный элемент устойчивости MVP.                                                                                       |
| R4  | Все операции auditable и воспроизводимы (логирование).                                                                                                                                                              | Требование к ИБ и юридической чистоте сделок.                                                                          |
| P   | Производительность (Performance)                                                                                                                                                                                    |                                                                                                                        |
| P1  | Среднее время ответа интерфейса — не более 300 мс для основных операций просмотра списка и подачи заявки.                                                                                                           | Архитектурно значимо: UX-болячка из текущей системы.                                                                   |
| P2  | Гарантия работы под высокой нагрузкой (ожидание X2 от текущей аудиитории, возможность горизонтального масштабирования фронта интернет-банка).                                                                       | Важно предусмотреть нагрузочный рост в случае удачной кампании.                                                        |
| P3  | Время обработки ручной заявки — не более 2 часов в рабочее время банка (но не влияет на критичный user journey).                                                                                                    | Выполнимый SLA, отражает реальное ожидание пользователя.                                                               |
| S   | Поддерживаемость (Supportability)                                                                                                                                                                                   |                                                                                                                        |
| S1  | Максимальное использование привычных для банка технологий (MS SQL/Oracle, существующие языки: C#, Java, PHP, React).                                                                                                | Обоснование: быстрое внедрение, дешевле сопровождение, выше качество поддержки.                                        |
| S2  | Документирование всех интеграций/новых сервисов для масштабирования автоматизации в будущем.                                                                                                                        | Ускоряет дальнейшую цифровую трансформацию.                                                                            |
| S3  | Легко подключаемый новый интерфейс для администрирования ставок: возможность расширить для других продуктов (кредиты, карты).                                                                                       | Масштабируемость бизнес-функции.                                                                                       |
| S4  | Модулярность для перехода части интернет-банка на микросервисную архитектуру (начать с блока "Депозиты").                                                                                                           | Важно для будущей работы с Kafka и отказа от монолита — снижает технический долг сразу.                                |
| +R  | + Ограничения (Restrictions)                                                                                                                                                                                        |                                                                                                                        |
| +R1 | Категорический запрет на прямой доступ интернет-банка к БД АБС (в новом процессе ставок/заявок).                                                                                                                    | Архитектурно-значимо: критичное требование для снижения нагрузки и повышения безопасности/разделения ответственности.  |
| +R2 | Хранение ставок — в централизованном сервисе или базе, доступной АБС и интернет-банку (например, отдельный модуль на Oracle/MS SQL или "хранилище ставок"), недопустимо использование xls-файлов в бизнес-процессе. | Критически важно для консистентности и auditable бизнес-логики, закладывает фундамент на масштабирование.              |
| +R3 | Интерфейс выставления ставок должен быть доступен обоим бэк-офисам с разграничением прав доступа.                                                                                                                   | Архитектурно значит для построения единой платформы.                                                                   |
| +R4 | Если используется очереди событий — только Kafka, но запускать только для сервисов, где платформа поддерживается.                                                                                                   | В интернет-банке не поддерживается — избегать "запуска ради запуска".                                                  |
| +R5 | HTTPS/TLS с современными параметрами + строгая обработка персональных данных (соблюдение закона о ПД и внутренних стандартов финсектора).                                                                           | Необходимое условие передачи чувствительных данных (архитектура и инфобезопасность).                                   |
| +R6 | Новую логику (API ставок, сервис заявок) выносить в отдельные сервисы или микросервисы, по возможности избегать затрагивания монолитных кусков старого интернет-банка.                                              | Обоснование: подготовка к микросервисной арх-ре и future-proof интеграциям; снижение рисков отказа канала при ошибках. |
| +R7 | Все новые компоненты должны быть задокументированы и покрыты автотестами (юнит/интеграция).                                                                                                                         | Снижение технического долга, ускоряет последующую доработку.                                                           |
| +R8 | Масштабирование АБС — только вертикальное, горизонтальное — только для приложений интернет-банка/витрины заявок.                                                                                                    | Важно для архитектурных решений по распределению нагрузки.                                                             |
